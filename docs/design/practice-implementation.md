# Practice interviews implementation

Apply migrations `0022_practice.sql` and `0024_private_sessions.sql` before deploying the practice API. Register `practice.router` under the existing `/v1` prefix. Sessions are encrypted with the account key and account RLS, and every read requires the selected profile. They are separate from `app.sessions`: no practice action starts or changes a real call or approves career facts.

The service uses the existing model-provider routing with the `pack` OpenAI model/reasoning settings or the configured Sonnet model. It prepares a topic plan and asks one adaptive question per turn. Responses are persisted before feedback generation. Follow-ups see the user's actual answer; model output is validated, scores use `practice-v1` (five dimensions, 0–4 with named anchors), and unsupported quotations are removed with an uncertainty note. Retries retain all original attempts, prior coaching exposure and compatible-rubric comparisons. Save toggles a question for later revisiting. Source questions must be explicitly selected from authorized stored interview transcripts, preserve their original text/location, and obey private-session ownership.

Start and action calls use UUID idempotency keys. Each operation is journaled before paid work. Repeated identical requests do not start duplicate generations; changed payloads return 409. Pause/finish/delete cancel pending generation and voice work, with replica cancellation checked about once per second. Completed attempts survive errors. An interrupted generation becomes explicitly retryable after five minutes; automatic replay does not create surprise provider charges. The maximum is 20 questions and ten attempts per question; prompts bound old answer history and source excerpts. Duration excludes pauses and completion occurs after the current answer receives feedback. A provider can still bill work accepted before cancellation.

Voice uses the existing `DEEPGRAM_API_KEY` and `COPILOT_DEEPGRAM_MODEL` for prerecorded recognition. `COPILOT_PRACTICE_TTS_MODELS` is a JSON language-to-Aura-voice mapping, defaulting to six provider-supported voices (en, es, fr, de, it, ja). Spoken language snapshots the shared 24-language profile capability setting. Recognition support and interviewer playback are separate capabilities; see [the current support matrix](../implementation/call-languages.md). Missing speech mappings or provider keys produce an honest 503 and the saved text flow remains available. The adapters call [Deepgram speech generation](https://developers.deepgram.com/reference/text-to-speech/speak-request) and [prerecorded transcription](https://developers.deepgram.com/docs/pre-recorded-audio), with model-improvement opt-out enabled. Production Deepgram account access and applicable opt-out pricing must be checked by the operator.

The desktop client records only its microphone with echo cancellation; playback must stop before recording. Interviewer questions are structured turns and never sent to recognition. Raw microphone bytes are accepted only on an explicit transcription action (8 MiB limit), kept in request memory and never retained in storage. `retain_audio:true` is rejected. Transcription output and generated speech are encrypted/cached in the session's operation records; deleting the session cascades to them. JSON/base64 media wrappers support the desktop's token-preserving native bridge, while raw upload/MP3 endpoints remain available for mobile.

Automated validation covers state transitions, source scope boundaries, durations, pause/resume, interruption recovery, skip/retry/coaching, rubric compatibility, quotation grounding, encrypted account/profile reads, and the actual provider HTTP contract using deterministic transports. Stack lifecycle tests are in `apps/api/tests/test_practice_stack.py`; they require the repository's PostgreSQL/Valkey/S3 stack. Production model quality, real provider permissions, microphone loss/switching, headphones/speaker echo, Windows/macOS device behavior and physical mobile audio require staged/device checks. They have not been inferred from mocked tests.
