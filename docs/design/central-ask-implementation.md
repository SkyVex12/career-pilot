# Central Ask deployment and lifecycle

Apply migration `0020_central_ask.sql` before deploying the API. The API uses existing core model provider settings and the `pack` OpenAI model/reasoning settings, or the configured Sonnet model for Anthropic/Bedrock. Credentials remain on the API server. No paid model calls are used in deterministic tests.

Conversations and their sealed message/source snapshots are account-owned, further selected by the active profile. Shared Career-OS profile access does not grant access to another account's conversations. Source queries run under active-profile RLS, and opening a citation rechecks current source access and transcript-storage consent.

Posting a UUID request id returns a pending message. Poll conversation detail for progressively available completion. Repeating the same request id does not create another generation; changing its payload returns 409. At most one answer is pending per conversation. Explicit retry reuses a failed/cancelled message and increments an attempt guard. Cancel aborts local work and another API replica observes cancellation within approximately one second while generating. Provider work already accepted may still incur charges. API restarts leave pending messages recoverable: after five minutes the next conversation read marks them failed and offers explicit retry, never automatic paid replay.

The retrieval window is bounded: 200 keyword-ranked approved memory facts, 60 applications, 1000 company-document sections, 90 work logs, and up to 100 saved calls with 2000 transcript segments distributed across calls. Explicit company/application/call/document and date filters apply before those limits. At most 12 ranked excerpts and eight matching-scope follow-ups enter the model. This is not an exhaustive search of all historical records: select a call or narrow dates for older evidence. Stored transcript consent is honored; missing transcript content is never invented. Current web retrieval is unavailable and general answers do not claim current verification.

Generated answers are retained snapshots. Deleting a source removes it from new retrieval and source resolution; it does not erase excerpts already present in retained answers. Deleting a conversation cascades to all messages, snapshots and pending work. Account/profile deletion also cascades. Draft persistence and the source drawer are handled by the desktop client.

Validation: `python -m pytest apps/api/tests/test_ask_unit.py -q` runs deterministic authorization, scope, injection-boundary, bounded ranking, transcript-consent and timestamp tests. `test_ask_stack.py` requires the repository's local PostgreSQL/Valkey/S3 stack and tests actual RLS, encrypted storage, duplicate requests, retry and deletion. Real-provider output quality and cancellation billing still require staged verification.
