## Interface and scope

Desktop keeps Call, Interview prep, Work context and Past calls. Practice is inside Interview prep; Ask is inside Work context. Settings contains background detection, optional calendars and account controls. Mobile groups these flows under Call, Interview prep, Work and History, with explicit desktop-companion attachment, phone-only capture, source inspection, saved-call practice imports and editable meeting preparation. Calls and practice share a 24-language catalog on compatible configured providers; availability is reported by the server, not inferred from an installed client.

## Activation checklist

Updating a client does not update the server. Before enabling these features on an intended development/staging deployment:

1. Deploy compatible API, gateway and worker source with the existing authentication, encryption keys, storage and provider configuration. Apply repository migrations through **0027** using the normal migration procedure. The worker must register `resume.original`; legacy uploaded resumes queue bounded extraction lazily into encrypted, content-hash-bound original-text fields. Scanned, malformed or oversized files remain explicitly unavailable. See [original resume extraction](resume-original-text.md).
2. Install the companion WebSocket proxy route. Preserve the exact `/v1/companion` location, HTTP/1.1 Upgrade/Connection headers and disabled proxy buffering from `docker/proxy/nginx.conf`. Its `$connection_upgrade` variable requires the accompanying `map $http_upgrade $connection_upgrade` in nginx's **http** context, not inside a server/location block. Map gateway/API upstreams to the actual host/container network; `127.0.0.1` is valid only when the services share that network namespace. Keep REST `/v1/companion/...` paths on the API. Validate nginx configuration and a real handshake before calling the deployment usable. The observed public Stage0 `/v1/companion` 404 is not fixed by this APK or by local forwarding evidence.
3. Configure language capability consistently in API and gateway. Compatible Deepgram Nova-3 recognition supports the shared 24-language catalog. Unset `COPILOT_CALL_LANGUAGES` enables the default catalog; remove a legacy explicit `COPILOT_VERIFIED_CALL_LANGUAGES=en` restriction or intentionally replace it with the desired list. Also review an old English-only `COPILOT_PRACTICE_TTS_MODELS` override. Only six catalog languages have configured Aura interviewer playback by default; other languages retain text questions and supported microphone/typed answers. See [language configuration](call-languages.md).
4. Optional calendar activation requires Google/Microsoft app registrations, exact callbacks and real owner consent. Optional remote personal-AI host access requires its reachable authenticated endpoint and consent flow. Neither is required to use ordinary Ask, practice or companion attachment. See [calendar setup](calendar-provider-setup.md) and [personal AI](personal-ai-context.md).
5. Use **HTTPS/WSS with trusted certificates** for production mobile release. Stage0 HTTP/WS and this isolated test variant are not production TLS. Production signing, Apple provisioning/notarization and store publication require the appropriate owner identities and release process.

No production mutation is implied or authorized by this checklist.

## Connecting the test phone to Stage0

Open desktop first if the VM is asleep; mobile does not implement VM wake. The last observed public address was API `http://35.184.116.247` and gateway `ws://35.184.116.247/v1/companion`. Confirm the current address after a VM restart; never enter the HTTPS wake-service URL as the API. A successful health/auth response does not prove the companion proxy or new feature routes are deployed.

The last read-only auth check found Google and Career-OS enabled and email codes disabled. Native Google sign-in is not configured in this mobile client. For an existing Google desktop account, first use desktop **Settings → Account → Sign-in → Add Career-OS sign-in**. Then sign into that same account and select the same profile on the phone; a separate account cannot see the existing desktop call.

Tap **Sign in with Career-OS** and approve on the provider's HTTPS page. The explicit test fallback ends at a browser cannot-connect page on `http://127.0.0.1:53683/callback?...`; that is expected because the phone has no desktop callback listener. Copy the entire address into the app and tap **Finish Career-OS sign-in**. The app validates origin/path, state, five-minute expiry and one-use PKCE exchange. Do not share that callback URL. Restart an expired attempt. The client does not silently create a separate account when linking proof is required.
